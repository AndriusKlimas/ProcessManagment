KinD setup for the music application
====================================

Prerequisites
-------------

- Docker Desktop must be running.
- kind and kubectl must be installed.
- Run all commands from the repository root:
  C:\Users\andri\Desktop\year3sem1\Production Precess\process-management-y-3

Automated setup
---------------

The repository includes setup-kind.ps1. Run it from PowerShell to perform the
full setup, including KinD, Samba, the SMB CSI driver, Redis Sentinel, Ingress,
local image builds, image loading, and application deployment:

    .\setup-kind.ps1

After the images have been built once, skip rebuilding them on later cluster
recreations:

    .\setup-kind.ps1 -SkipImageBuild

If PowerShell blocks local scripts, allow scripts for only the current terminal
session and run the setup again:

    Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
    .\setup-kind.ps1

Create the KinD cluster
-----------------------

The repository includes kind-config.yml, which creates one control-plane node
and two worker nodes. It also maps ports 80 and 443 from KinD to the local
computer.

    kind create cluster --config .\kind-config.yml

Start the local Samba share
---------------------------

Start Samba after KinD so the Docker Compose service can attach to KinD's
Docker network:

    docker compose -f .\samba\docker-compose-samba.yml up -d --build

The share is available inside KinD as //samba/sambashare. Put song files in:

    .\samba\storage\html

Install the Samba CSI driver
----------------------------

Helm is not required. Install the Linux KinD driver directly with kubectl:

    $version = "v1.18.0"
    $base = "https://raw.githubusercontent.com/kubernetes-csi/csi-driver-smb/$version/deploy/$version"
    kubectl apply -f "$base/rbac-csi-smb.yaml"
    kubectl apply -f "$base/csi-smb-driver.yaml"
    kubectl apply -f "$base/csi-smb-controller.yaml"
    kubectl apply -f "$base/csi-smb-node.yaml"

Verify the driver:

    kubectl get pods -n kube-system -l app=csi-smb-controller
    kubectl get pods -n kube-system -l app=csi-smb-node -o wide

Install the NGINX Ingress Controller
-------------------------------------

    kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml

Wait until the controller is ready:

    kubectl wait --namespace ingress-nginx `
      --for=condition=ready pod `
      --selector=app.kubernetes.io/component=controller `
      --timeout=180s

The host ports are mapped on the control-plane node. Pin the Ingress
controller there so requests from localhost reach it:

        kubectl patch deployment ingress-nginx-controller `
            --namespace ingress-nginx `
            --type=merge `
            --patch-file .\ingress-controller-patch.json

Wait for the controller rollout to finish:

        kubectl rollout status deployment/ingress-nginx-controller `
            --namespace ingress-nginx `
            --timeout=120s

Create the application namespace
--------------------------------

The Kubernetes manifests use the music-app namespace. Create it before
applying the application resources:

    kubectl create namespace music-app --dry-run=client -o yaml | kubectl apply -f -

Install Redis Sentinel
----------------------

Install the Bitnami Redis chart with the values in redis\redis-values.yml:

        helm repo add bitnami https://charts.bitnami.com/bitnami --force-update
        helm repo update bitnami
        helm upgrade --install redis bitnami/redis `
            --namespace music-app `
            --create-namespace `
            --values .\redis\redis-values.yml

Wait for the Redis primary, replicas, and Sentinel sidecars:

        kubectl rollout status statefulset/redis-node `
            --namespace music-app `
            --timeout=300s

Check the Redis pods and services:

        kubectl get pods -n music-app -l app.kubernetes.io/name=redis
        kubectl get service redis -n music-app

Deploy the application
----------------------

Apply the development overlay from the repository root. Do not apply only
base\deployment, because the development overlay also adds the localhost
Ingress configuration.

    kubectl apply -k .\base\dev

Check the deployment
--------------------

    kubectl get pods -n music-app
    kubectl get services -n music-app
    kubectl get ingress -n music-app

Wait until the application pods show Running or Completed. If a pod is not
starting, inspect it with:

    kubectl describe pod <pod-name> -n music-app
    kubectl logs <pod-name> -n music-app

Open the application
---------------------

The Ingress currently defines these paths:

    http://localhost/get-catalog
    http://localhost/login-page
    http://localhost/add-product-page
    http://localhost/play-songs
    http://localhost/history-page

The root URL http://localhost/ is not currently configured by the Ingress.

Build and load Docker images
----------------------------

This setup uses locally built images. Build the six application images with
the tag used by the development manifests:

    docker build -t andriuskl/catalog-svc_1:3.0.1 .\catalog-svc
    docker build -t andriuskl/shop-front-svc:3.0.1 .\shop-front-svc
    docker build -t andriuskl/product-admin-svc:3.0.1 .\product-admin-svc
    docker build -t andriuskl/song-player-svc:3.0.1 .\song-player-svc
    docker build -t andriuskl/history-svc:3.0.1 .\history-svc
    docker build -t andriuskl/login-page-svc:3.0.1 .\login-page-svc

Load each image into KinD. For example:

    kind load docker-image andriuskl/catalog-svc_1:3.0.1 --name music-app
    kind load docker-image andriuskl/shop-front-svc:3.0.1 --name music-app

Repeat the load command for the other four images. Because the deployment
manifests currently use imagePullPolicy: Always, Kubernetes may still try to
pull these images from Docker Hub. Change that policy to IfNotPresent in the
deployment manifests when using only local images.

If pods show ImagePullBackOff, check the image names, tags, and pull policy.

The application overlay creates the smbcreds Secret, smb StorageClass, and
song-storage PVC. It mounts the PVC into song-player-nginx at
/usr/share/nginx/html. Check the claim after applying the overlay:

    kubectl get pvc -n music-app
    kubectl get pv

Port 80 already in use
----------------------

If cluster creation fails because port 80 is already in use, change hostPort
from 80 to 8080 in kind-config.yml. Recreate the cluster and use:

    http://localhost:8080/get-catalog

Stop and remove the cluster
---------------------------

To remove only the application resources, leaving the KinD cluster and Redis
Sentinel running:

    kubectl delete -k .\base\dev

Because Redis Sentinel was installed with Helm, remove it separately if you
also want to remove Redis while keeping the cluster:

    helm uninstall redis --namespace music-app

To free the most laptop memory, delete the entire KinD cluster. This removes
Redis, Ingress, the SMB CSI driver, and all application resources at once:

    kind delete cluster --name music-app

Finally stop the separate Samba Docker Compose container:

    docker compose -f .\samba\docker-compose-samba.yml down

For a complete laptop shutdown, use:

    kind delete cluster --name music-app
    docker compose -f .\samba\docker-compose-samba.yml down
